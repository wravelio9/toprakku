# Dark Mode Toprakku Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a user-selectable dark mode that follows system preference by default and persists the choice.

**Architecture:** Semantic Tailwind tokens in `globals.css` resolve through CSS variables; a small client `ThemeProvider` sets `data-theme` on `<html>`, and an inline script sets it before first paint. Component classes use the semantic tokens, with permanent dark panels mapped to a dedicated `night` token.

**Tech Stack:** Next.js 16 App Router, React 19, Tailwind CSS 4, lucide-react.

**Spec:** `docs/superpowers/specs/2026-11-25-dark-mode-design.md`

## Global Constraints

- No `new Date()` or `localStorage` reads during prerender (Cache Components enabled).
- ESLint forbids synchronous `setState` in an effect body; defer client reads with `setTimeout(..., 0)`.
- Indonesian copy in the UI.
- No new dependencies.

## Review Focus

- First paint in dark mode must not flash light: inline head script runs before hydration.
- `bg-white` cards and inputs must become `bg-surface`, or they stay glaringly white in dark mode.
- Permanent dark panels (footer, testimonials, overlay, toast) must not invert when tokens swap.
- Accent buttons with `text-white` on `bg-chili`/`bg-leaf` must keep white text.
- Toggling must persist and survive a full reload.
